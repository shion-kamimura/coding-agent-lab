# 同じ修正課題でClient SDKとAgent SDKを比較する

## 目的・条件・再現方法

仮説は「課題を共有すれば、手動ループに残る制御点とSDKへ委任する部分を比較できる」。
一般的な性能順位を決めるベンチマークではない。
2026-11-11、Python 3.15.2、anthropic 2.3.0、claude-agent-sdk 0.2.180、
同梱CLI 2.1.321、`claude-haiku-5-5`で確認した。

両方式は`repair_exercise.py`の初期コード・固定4テスト・操作制約・system文・質問・
最終確認を共有する。毎回新しい一時ディレクトリを使い、関数修正とテスト成功を検査する。
モデルは両方とも推論disabled。実行順はClient→Agent、Agent→Client、Client→Agentとした。

```bash
# 開発手順に従ってインストールし、ANTHROPIC_API_KEYを設定する。
# 以下は有料APIを両方式で各3回呼ぶ。応答回数はモデルの選択による。
LLM_MODEL=claude-haiku-5-5 python experiments/compare_repair.py
```

比較スクリプトは実SDKメソッドをラップし、元のメソッドをそのまま呼ぶ。
応答を模擬せず、ClientのMessage.usageとAgentのResultMessage.usageを記録する。
SDK応答を置き換えるオフラインテストとは異なる。計測には生成・前後の固定テスト・
SDKの起動終了も含む。APIキー、プロンプト、モデル本文は出力しない。

## 実モデルの観測結果

| 方式 | 回 | 成功 | 秒 | API要求／SDK報告ターン | 非キャッシュ入力 | キャッシュ作成 | キャッシュ読込 | 出力 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Client | 1 | 成功 | 5.22 | 5要求 | 5537 | 0 | 0 | 492 |
| Agent | 1 | 成功 | 4.94 | 5ターン | 8 | 3043 | 7537 | 503 |
| Agent | 2 | 成功 | 4.88 | 5ターン | 8 | 1354 | 9242 | 520 |
| Client | 2 | 成功 | 4.34 | 5要求 | 5489 | 0 | 0 | 440 |
| Client | 3 | 成功 | 4.17 | 5要求 | 5411 | 0 | 0 | 423 |
| Agent | 3 | 成功 | 4.44 | 5ターン | 8 | 1340 | 9220 | 472 |

Clientは応答ごとのUsageを合計し、AgentはSDKの最終Usageを使った。単位はトークン。
非キャッシュ入力だけを比べるとAgentの利用量を過小評価するため、キャッシュ分を分けて示した。
いずれも`a - b`→`a + b`と最終テスト成功を確認した。
Clientの時間中央値は4.34秒、Agentは4.88秒だが、各3回の単一課題なので優劣は判断しない。
料金単価を適用した費用比較は未実施。

## 制御と実装量

| 処理 | Client SDK版 | Agent SDK版 |
| --- | --- | --- |
| API要求 | `messages.create()`と設定を直接記述 | SDK内部 |
| ツール | スキーマ、名前・引数検査、Read/Editの実行を記述 | 組み込みRead/Edit、PreToolUse、専用MCPテストツール |
| 履歴 | assistant全体と対応IDのtool_resultを追加 | SDK内部 |
| テスト失敗からの修正 | 結果を履歴に加え次の要求へ進む | SDKの反復で結果を受け取り継続 |
| 停止 | API要求数、終了理由、単一ツール、最終本文を直接判定 | max_turns等とResultMessageを確認 |
| 成功 | 共有課題の固定テスト・最終ソース・差分を検査 | 同じ検査に加えSDK正常終了を要求 |

初版の物理行数はClient版144行、Agent版137行、共有課題155行（空行・説明含む）。
量の差は小さく、Agent版にも権限制御とMCP接続が必要だった。
Client版ではAPI要求・履歴・停止を直接変更できる点が今回の学習目的に合う。

## 検証と限界

オフラインでは実Client SDKとMockTransportで、誤修正`a * b`→固定テスト失敗→
結果返却→再修正`a + b`→再テスト成功→最終確認まで検証した。
失敗テストはツール異常ではなく、非ゼロの終了コードを含む通常の観測結果である。
操作拒否からの回復、未テスト・古い結果、API異常、各要求上限も確認する。
実モデルの6試行では最初の修正が成功しており、実モデルの再修正能力の証明ではない。

Agent SDKは内部の追加プロンプト、組み込みツールの入出力、キャッシュ管理が異なる。
Clientは4096出力トークン・30秒timeout・再試行0・最大12要求、Agentは最大8ターン・
0.25 USDしきい値・SDKセッション120秒。要求とターンの上限は同一単位ではない。
同じ課題とモデルによるエンドツーエンド比較であり、API要求を完全同条件にはしていない。
品質・費用・速度の一般的な優劣や、任意リポジトリへの拡張性は未検証である。
