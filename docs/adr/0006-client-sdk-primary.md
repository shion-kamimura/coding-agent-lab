# ADR 0006: ループの学習をClient SDKで進め、Agent SDKを比較用に残す

- 状態: 採用（#23）
- 日付: 2026-11-11

## 背景と決定

将来、ループ・グラフの構成、失敗からの戻り先、状態と成功判定を設計するために、
まず公式Client SDKを使う手動ループで修正・テスト実行まで扱う。
ユーザーと合意した学習方針であり、Agent SDKの機能不足を理由とする全面的な置換ではない。
Agent SDKは外側の業務グラフから呼び出す実装作業者としても利用できる。

ADR 0005の最小例を比較用に維持し、同じ課題・固定テスト・成功判定を共有する。
共有対象は`repair_exercise.py`の課題と操作契約に限る。
各SDKの公開応答・例外・ループ・終了状態はそれぞれ直接使い、独自Clientや共通応答型を作らない。

## 代替案と影響

Agent SDKを主軸にすればRead・Edit・履歴と反復を再利用できる。
今回はそれらを直接書いて制御点を学ぶ目的を優先し、Client SDKの実装を追加する。
コードとテストが増える代償があり、Agent SDKより本質的に高品質・高速・低費用だとは判断しない。

テストの非ゼロ終了は観測結果としてモデルへ返し、上限内で再修正できる。
操作拒否は安全なエラー結果、API・想定外の操作内部エラーは停止として区別する。
共有課題のテスト実行エラーは両方式とも固定文言の結果へ変換する。
再修正後にもモデルからのテストとアプリの最終確認を必要とする。

今回は小さな手動ループに留める。グラフエンジンや永続状態、任意コードの実行は、
分岐・再開・隔離の要件が具体化した段階で選定する。
比較の再現手順と限界は [実験記録](../../experiments/repair-sdk-comparison.md) にまとめる。
