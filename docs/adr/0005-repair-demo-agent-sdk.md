# ADR 0005: 修正・テスト実行の学習例にAgent SDKを使う

- 状態: 採用（#21の最小例）
- 日付: 2026-11-10

## 背景

読取専用調査の次に、ファイルを修正し、固定テストを実行して結果を確認する。
まずアプリが生成する整数加算の課題で、SDKに任せる反復とアプリの成功判定を学ぶ。
任意リポジトリ・汎用コマンド実行は今回の範囲に含めない。

## 比較

| 選択肢 | 再利用できる部分 | 今回必要な追加・制約 |
| --- | --- | --- |
| Client SDKの手動ループ | 現在の通信・公開型・既存MockTransport検証 | Edit、テスト操作、履歴、反復をアプリで実装する |
| Client SDKのTool Runner | 履歴・ツール実行・反復 | Editとテスト操作は自作。既存比較で例外本文を結果へ返す挙動があり、今回も制御が必要 |
| Agent SDK | Read・Edit、Claude Codeの履歴と反復、hooks、独自SDK MCPツール | 同梱CLIへの依存、非同期処理、操作範囲と成功判定の検証が必要 |

## 決定

新しい学習例だけにAgent SDKを採用する。編集と反復を再実装せず、公式例の
Read・Edit・PreToolUse・SDK MCP serverを使って責務の境界を確認する。
既存のClient SDKによる実行例とADR 0004の読取専用調査は置き換えない。

一般的なBashを許可する代わりに、引数なしの固定テストツールを提供する。
モデルが任意Pythonを書いて実行する構成を先取りせず、関数の構文を3つの純粋な
算術式に限定して実行前に照合する。テストの不変・前後の実行結果・差分で成功を判定し、
SDKの正常終了は必要条件の一つに留める。

`tools`によるツール集合の限定、全操作を検査する`PreToolUse`、設定・MCPの取込制限を
組み合わせる。`allowed_tools`だけで隔離を実現したとは判断しない。
教材と使用版は [利用ガイド](../repair-demo.md) にまとめる。

## 影響と再検討条件

`claude-agent-sdk>=0.2.180,<0.3`を依存へ追加する。CLI同梱により配布サイズが増え、
非同期処理とCLIとの統合検証も必要になる。最小例のため外部サーバーは追加しない。
0.x版の将来の互換性は保証せず、依存更新時は使用版と同梱CLIで再検証する。
SDKの公開型を直接使い、独自Client・SDK共通型・汎用ワークフロー層は作らない。

この選択はAgent SDKへの全面移行ではない。実用コードの編集・コマンド実行へ進むときは、
OS隔離、承認、差分レビュー、テスト保護、依存・ネットワーク・実行予算を再設計する。
限られた構文の課題を解けたことを、任意コードを扱える証拠にはしない。
