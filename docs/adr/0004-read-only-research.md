# ADR 0004: 読み取り専用調査にClient SDKの手動ループを使う

- 状態: 採用（#18の範囲）
- 日付: 2026-11-10

## 背景

必要なのは限定したファイルの一覧・範囲読み取り、安全な失敗からの再調査、反復上限、
引用照合です。既存の加算例とClient SDKのループを維持し、将来の編集・コマンド実行を
先回りして実装しません。参照した公式資料と確認範囲は [利用ガイド](../file-research.md) にあります。

## 比較

| 要件 | Client SDKの手動ループ | Agent SDK |
| --- | --- | --- |
| ファイル操作 | `ToolParam`でアプリの2操作だけを公開し、実行前に引数と範囲を検証 | 組み込みRead等、または独自ツールをSDK MCP serverへ登録。今回と同じ細かい契約なら独自実装が必要 |
| 権限 | アプリのディレクトリFD・許可リストで制限 | `cwd`、ツール設定、permission callback・hooks等を組み合わせる。`allowed_tools`は自動承認リストでありツール集合やファイル隔離そのものではない |
| 履歴・終了 | `MessageParam`と`tool_result`をアプリが管理。API要求数を直接数える | Claude Code側のループ・`max_turns`等へ委譲。アプリのAPI要求回数と同じ単位とは仮定できない |
| 安全なエラー | 既知エラーだけモデルへ返し、未知エラーは履歴へ追加する前に停止 | 独自ツール・hooks・SDKメッセージで設計し、例外がどこへ伝わるか検証する必要がある |
| オフライン検証 | 既存の実SDK＋MockTransportで要求・履歴を確認できる | Python依存に加えて同梱Claude Code CLIを使う。独自ツール単体とCLIとの統合を分けて検証する必要がある |
| 将来の編集・テスト | アプリで操作・承認・隔離を追加する必要がある | 組み込みツール・コンテキスト管理を再利用できる。採用時もアプリの権限・停止・検証方針との照合が必要 |

## 決定と影響

今回はClient SDKを継続します。2操作の境界と反復・失敗を既存の通信テストで直接確認でき、
Agent SDKの実行基盤や権限設定を追加する必要がないためです。独自Client・共通型・例外変換層は
作りません。通信・公開型はSDKへ、ファイル操作・履歴・回数・引用照合はアプリへ分担します。

Tool Runnerは [既存比較](../../experiments/tool-runner.md) で未知エラーの本文が
ツール結果へ変換され得る点を確認済みです。即停止の契約を維持するため今回は使いません。
既知の操作拒否は今回のアプリで安全な結果へ変換します。

代償は、ツール定義・履歴更新・停止判定をアプリが維持することです。今回のファイル調査を
加算例と大規模に共通化せず、短いループとして分離します。編集・テスト実行・長期セッションへ
進む際はAgent SDKを再比較し、この決定を全用途への恒久的な固定にはしません。
Agent SDK自体を動作検証した比較ではなく、公式資料に基づく選定です。
