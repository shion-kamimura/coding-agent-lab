# ADR 0003: 公式教材と公式SDKを中心に実装する

- 状態: 採用
- 日付: 2026-11-01
- 置換対象: [ADR 0002](0002-llm-client.md) の独自Client・型・例外変換と、自作を学習の前提とする方針

## 背景

PR #6はAnthropic公式SDKの上に独自のメッセージ・応答・使用量・共通例外とClientを設けました。
複数プロバイダーの実装は現在の要件になく、次のTool Callingのためにはテキスト専用の契約を
拡張する必要があります。SDKの型と独自の型の両方を学び、変換コードを維持する負担があります。

学習の目的は実装の仕組みと設計理由の理解です。コードはAIが作り、ユーザーは公式資料と
実装を対応づけて学びます。自作の範囲や質問への回答を学習の前提にする必要はありません。
公式講座には、最小のAPI呼出しから手動ループ、Tool Runnerへ進む教材があります。

## 決定

- 「公式資料を読む → 資料に沿って実装する」の二段階を基本にします。
  質問による理解確認や説明の提出は標準手順にせず、ユーザーが希望する場合に行います。
- Claude Platform 101を入口とし、詳しいAPI講座やTool Callingの改善講座を必要な順に使います。
  教材と実装の対応・変更点・検証範囲を示し、技術ブログは設計上の疑問を補う資料にします。
- 公式Client SDKのAPI・型・例外を直接使い、独自Client・設定クラス・共通型・例外階層を廃止します。
  SDKからの応答を共通のテキスト応答へ変換せず、用途に応じてSDKのフィールドを参照します。
- 現在は`llm.py`を、`Anthropic`をwith文で使って`messages.create()`を呼ぶ実行例にします。
  固定の質問への回答を表示し、正常終了の確認・空本文の判定・エラー詳細を表示しない判断は残します。
- 既定のHaiku、環境変数によるSonnetへの手動切替、出力16,000、adaptive・medium、
  通信タイムアウト30秒、SDKの再試行2回は維持します。実測した最適値とはしません。
- Tool Runner（Beta）やAgent SDKの利用は、それぞれの責任と必要な制御を照合して決めます。
  今回Tool Calling・Agent Loop・Agent SDKへの移行は実装しません。

## 代替案と影響

独自Clientの維持はSDKの変更箇所をまとめられますが、現時点では単一プロバイダーの
学習コードに必要な利点より、変換と独自契約を維持する負担が大きいと判断しました。
今回の変更は旧Client APIとの互換性を保ちません。利用方法は
[公式SDKの利用ガイド](../llm-client.md) に置きます。

公式SDKを使ってもバージョン変更の影響はあります。公開API・依存のバージョン範囲を使い、
更新時の型検査とアプリ側の挙動を確認します。将来、複数プロバイダーや共通契約が
具体的な要件になった場合は、改めて抽象化を検討できます。

Agent SDKへ全面移行する案は、まだツールやアプリ固有の制御要件がないため今回は採用しません。
SDKを使う方針と、コーディングエージェントのループ全体をSDKへ任せる判断を区別します。

## 検証

実際のClient SDKと模擬HTTP通信を使い、実行例が送る設定、表示・終了の判断、接続終了を
検証します。SDKの全機能を再検証せず、削除した変換層だけを対象とするテストも削除します。
品質チェックとwheelのインストール検証を行います。実APIの有料疎通・品質・設定値の実用性は
通常のオフライン検証の対象外です。
