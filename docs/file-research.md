# 読み取り専用のファイル調査（#18）

起動側が指定したファイルをモデルが調べ、参照ファイル・行番号・引用を添えて回答します。
製品CLI、編集、コマンド実行、並列ツール、永続化、コンテキスト圧縮は対象外です。
SDK選定は [ADR 0004](adr/0004-read-only-research.md) にあります。

## 教材と実装

2026-11-10に公式GitHubのClient SDK [tools.py](https://github.com/anthropics/anthropic-sdk-python/blob/main/examples/tools.py)
とAgent SDK [README](https://github.com/anthropics/claude-agent-sdk-python/blob/main/README.md)
を読みました。前者の`ToolParam`、`tool_use`、assistant履歴と`tool_result`の往復を
[file_research.py](../src/coding_agent/file_research.py) に対応づけています。
教材の天気ツールをファイル調査へ変更し、入力検証、反復上限、安全なエラー、引用照合を追加しました。
これらは教材からアプリ側で補った仕様です。

[公式ツール利用チュートリアル](https://platform.claude.com/docs/en/agents-and-tools/tool-use/build-a-tool-using-agent)、
[Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)、
[Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows)
も関連資料です。今回は公式サイトへの通信が環境で拒否され、本文を再確認できていません。
Thinking・Context managementの全教材の読了や、ユーザーの理解を認定するものではありません。
推論は既存例と同じく無効にし、必要な範囲の読み取りと結果上限で履歴の増加を抑えます。
要約・圧縮は実装していません。

## 呼び出し方

開発依存の導入は [開発手順](development.md) を参照してください。
以下はPython 3.15、POSIX/Linux用の呼び出し例です。実APIの料金が発生します。
`ANTHROPIC_API_KEY`を環境変数へ設定し、必要なら`LLM_MODEL`を変更します。
既定モデルは既存例と同じ`claude-haiku-5-5`です。

```python
from pathlib import Path
from coding_agent.file_research import research

print(
    research(
        "このプロジェクトのテスト実行方法を、前提条件とともに説明して。",
        root=Path.cwd(),
        allowed_files=("README.md", "docs/development.md", "pyproject.toml"),
        max_steps=12,
    )
)
```

起動側が信頼できるルートと**個々のファイル**を指定します。モデルにはルート変更や
許可範囲変更の操作を提供しません。許可リストは起動時に固定されます。
ファイル名は一覧から探せるので、質問に許可リストを埋め込む必要はありません。
調査経路やツール回数は固定しません。既存の加算例はそのまま使えます。

## 操作の契約と上限

[file_tools.py](../src/coding_agent/file_tools.py) がアプリ側で強制します。

| 項目 | 契約・理由 |
| --- | --- |
| 許可範囲 | 相対ファイル名1〜256個。名前はUTF-8で240バイト以下。初版の小さな調査と一覧サイズを有限にする |
| 名前 | `/`区切り。空要素、`.`で始まる要素、バックスラッシュ、コロン、制御文字を拒否。絶対パス、`..`、`.git`、`.env`も拒否 |
| ファイル種別 | 通常ファイルのみ。拡張子は`.md .txt .rst .py .toml .yaml .yml .json`。UTF-8を厳密にデコードし、NUL等のC0制御文字（改行・CR・タブ以外）を拒否 |
| リンク | 各要素をルートFDから`dir_fd`と`O_NOFOLLOW`で開く。途中のディレクトリもリンクをたどらない。FIFO等は非ブロッキングで開いて種別を検査 |
| `list_files(path)` | ルートは`.`。許可ファイルとその祖先ディレクトリだけを、名前順で最大50件返す。リンク・特殊ファイル・不存在は一覧から除く。ディスク全体の一覧ではないと明示 |
| 一覧省略 | `omitted`を返す。ページングは初版の対象外で、省略された名前が必要なら起動側が許可範囲を絞る |
| `read_file(path, start_line, line_count)` | 1始まり。開始行1〜262144、行数1〜100。上限外の指定はエラー。bool・文字列を整数として受け付けない |
| 入力サイズ | 1ファイル256 KiBまで。超過は全文をモデルへ渡さずエラー。遠い開始行の探索や巨大ファイル読取も有限にする |
| 結果サイズ | 本文のUTF-8バイト数（行ごとに改行1バイトを加算）で16 KiBまで。JSONのエスケープ・メタデータは別。完全な行だけを返す。先頭の1行が収まらない場合はエラー |
| 範囲表示 | `start_line`、`end_line`、行番号付き`lines`、`has_more`、`omitted`。EOF以降は空配列と`end_line=null`。全文と部分読取を区別 |
| 反復 | `max_steps`は1〜128、既定12。最終回答のAPI要求も1回に数える。再調査も同じ上限内。1応答1ツール要求、複数要求は実行前に停止 |
| API | 1要求4096出力トークン、timeout 30秒、SDK再試行0。上限を超えるAPI要求を行わない。厳密な費用・全体時間の予算ではない |

件数・サイズはコードの定数で、モデルから変更できません。反復数だけは呼び出し引数です。
行はPythonの`str.splitlines()`で区切り、改行コードを除いた文字列を引用対象にします。
ファイル全体が空なら空配列です。行は短縮せず、そのまま返します。

禁止名や拡張子は秘密情報の完全な検出ではありません。**許可する内容は起動側が事前に確認**します。
通常ファイルでも秘密情報を含み得ます。ハードリンク、マウント変更、同時編集を隔離する仕組みでは
ありません。ルートの祖先と調査中のファイルシステムは起動側が管理し、調査中は変更しない前提です。
ルート自身のシンボリックリンクは拒否します。Windows対応は未実装です。

## エラーと回答の確認

不存在、権限拒否、範囲外、上限外、非UTF-8等は固定文言の`error`と`is_error=true`を
モデルへ返し、一覧の再確認・別パス指定へ戻れます。生のOS例外本文やホスト絶対パスは返しません。
SDK通信失敗・想定外の内部エラーは固定文言で即停止し、その後のAPI要求をしません。
途中のモデル本文・推論・例外・ツール結果を標準出力やログへ自動表示しません。
ファイル本文の指示はデータとして扱うようsystemで指示し、操作権限はコードで固定します。
プロンプトだけで任意の誘導を完全に防げるとは扱いません。

最終回答はJSONの`findings`（path・line・quote・explanation）と`limitations`です。
SDKの`output_config.format`にJSON Schemaを渡し、構造化出力で回答形式を指定します。
プロンプトだけでは前置き・コードフェンス・後続説明が付く実応答を確認したためです。
構造化出力でも引用の正しさは保証されないため、以下のアプリ側の検査を維持します。
読取根拠が得られるまでは`tool_choice.type=any`で調査操作を要求し、根拠取得後は
`auto`でモデルが追加調査か最終回答かを選びます。構造化出力だけを指定した際の
未調査・空findingsでの終了を避けるためで、反復上限と空findingsの拒否は維持します。
ツール結果の日本語はJSONのUnicodeエスケープへ変換せず渡し、引用の転記を助けます。
空の回答、空のfindings、未読の場所、行番号や引用が一致しない回答は未完了として停止します。
照合には実際に返却した完全な行を使い、未返却の行を裏で読み足して承認しません。
引用全体が一致した後にだけ表示用文字列を返します。

ただし引用の一致は、説明の意味や質問への十分性を保証しません。出力には
「引用照合済み（説明・課題達成は要確認）」と表示します。成功の自動判定は提供しません。
レビューではコマンドと前提条件が引用に沿っているか、重要な前提を落としていないかを確認します。
根拠が得られないときは、モデルは未確認を示すよう指示されていますが、findingsが空なら
アプリは未完了にします。

## 検証と限界

[オフラインテスト](../tests/test_file_research.py) は一時ディレクトリと実SDKの
`httpx2.MockTransport`で、次を確認します。

- 不存在 → 一覧 → README → 開発手順 → Pythonの前提・インストール・pytestの回答。
- 許可範囲、リンク、特殊ファイル、文字コード、サイズ、行範囲、一覧・本文の省略。
- 拒否の反復、API・内部エラー、引用の捏造・未読・空回答の拒否。

模擬回答は期待するコマンド・前提条件・根拠行を固定しています。実モデルが自分で正しい
参照を選べることや、説明の意味が正しいことの証明ではありません。
実APIでは`claude-haiku-5-5`と許可ファイル3個でテスト手順の調査を実行し、
構造化出力・ツール往復・引用照合まで確認しました。単一の質問での確認であり、
一般的な根拠選択・回答品質、料金の集計、Windowsは未検証です。
実行済みチェックと対象SHA・CIの状態は対応するPRの検証欄へ記録します。
